Recipe file format

A recipe is a saved set of image-control settings for the GR IIIx. This describes a plain-text file, RECIPES.TXT, that holds a library of them, and the offline checker tools/recipes.py.

The file is not installed on the camera and needs no firmware change. It is a reference you keep on a phone or computer: the checker prints each recipe as a dial-in list for the in-camera RAW development screen (playback → RAW Development), or for the two Custom image-control slots that the Wi-Fi API can switch between. The values and the rules come from the firmware (see Firmware modification: feasibility §4.3-4.4).

File layout

  • UTF-8 text in the card root, named RECIPES.TXT.
  • First non-blank line: format 1, or format 2 when the file uses a format-2 setting. Format 2 is a superset; a format-1 file stays valid.
  • Each recipe is a [Name] header followed by key = value lines.
  • # starts a comment. Blank lines are ignored. Names are case-insensitive for keys and values; recipe names keep their case.
  • A setting that is left out is simply not dialled in; it is not forced to 0. That matters: the camera's defaults are not 0 for every control (Negative Film starts at High/Low Key +2, Contrast (Shadow) −1, per the GR Blog).
  • At most 64 recipes; names at most 32 characters. (The camera cannot name a Custom slot, so the name only lives in the file and the app.)
# GR recipes, format 1
format 1

[Warm Slide]
control = positive_film
saturation = +1
hue = -1
contrast = +1
contrast_highlight = -1
shading = -1
clarity = +1

[Street Mono]
control = hard_monotone
key = -1
contrast = +2
toning = sepia
grain = 2

Keys

control is required. Its value is one of:

standard, vivid, monotone, soft_monotone, hard_monotone, hi_contrast_bw, negative_film, positive_film, bleach_bypass, retro, hdr_tone, cross_process.

Key Values Notes
saturation, hue, key, contrast, contrast_highlight, contrast_shadow, sharpness, shading, clarity -4..+4 nine steps
toning monotone controls: none, sepia, red, green, blue, purple; bleach bypass: none, cool, warm (the menu's --, C, W); retro: -4..+4 (written -1, 0, +1); HDR tone: none, bw, sepia; cross process: basic, magenta, yellow meaning depends on the control
filter none, 1, 2, 3, 4, custom monotone family only
grain 0..3 0 = off; 1–3 = Low, Mid, High
hdr_strength 1..3 HDR Tone only; Low, Mid, High

Each control supports only some parameters. The checker rejects a parameter the control does not have (for example saturation on a monotone control, or clarity on Soft Monotone). The supported sets follow the camera's capability table (feasibility doc §4.4). Cross Process, added in firmware 1.30, has every colour parameter (saturation through clarity) plus toning: its UserData names list them all.

Format 2: shooting settings and recipe information

Published recipes also set white balance, exposure and the corrections. Format 2 adds these keys. They suit every control. In a format 1 file they are an error (line 4: 'wb' needs 'format 2').

The checker writes format 1 whenever no recipe uses a format-2 key, so format-1 files keep their exact form.

Value sets from the firmware

The engineering shell command UserData Set <name> <value> (0x53008038, parser 0x5334688c; see GR mod landscape §7) compares the setting name, then calls one matcher per name. Each matcher compares the value text against a fixed list and passes a code to a setter. Reading those lists (Read; GR IIIx 1.60) gives the value sets above:

Not settled by these lists (Not verified on a camera):

  • The Kelvin step (published recipes use 5250K, so at most 50K) and the exact exposure and ISO limits.
  • Whether any of these writes survive a power cycle. UserData Set has never been run on this camera.

The recipe name is the one part of a recipe the camera has no setting for.

Checked on the camera

In-camera RAW developments of R0006328 on 2026-11-20 (R0006333–6336), read from the maker notes (Read):

  • Bleach Bypass toning "C" is stored as 2 in tag 0x0247 slot 14, so "--" is Normal (1) and W is Warm (3).
  • Retro toning +3 is stored as 3 in tag 0x0247 slot 8, a signed scale.
  • White balance Daylight with shift A3 G2 is stored as WBShiftAB −3, WBShiftGM +2: in the maker note blue and green count positive. The file format uses the camera's letters (a3, g2), so it is not affected.
  • Maker note ImageTone codes: 256 Standard, 262 Positive Film, 263 Bleach Bypass, 264 Retro, 267 Negative Film.

Sending a recipe to Custom 1 or 2 (test, not yet run)

recipes.py --userdata 1 prints a recipe as UserData Set lines: the slot's image control first (StillImageControlNo1 NegativeFilm), then its parameters, then white balance and the corrections. Every name it can produce (244) is present in the 1.60 firmware (checked against the decoded image). A recipe's settings that it leaves out are not sent, so the slot keeps them. Not sent yet:

  • filter: the firmware's FilterEffectCustom takes OFF, Custom1…Custom4; which filter colour each means is not known.
  • exposure: CommonXv is a float and probably exposure compensation, but that is not confirmed.
  • iso, iso_max: no UserData setting found.

tools/recipe_card.py carries the lines to the camera over Wi-Fi. recipe_card.py card writes a card with SCRIPT/STARTUP.TTL and SCRIPT/RECIPE/. The script starts a small HTTP endpoint on port 8080 and relays shell lines to the RTOS, as the AF remote card does (tools/af_debug_card.py --remote). It has nothing else: no AF logging, no patch loader, no RAM access. The relay takes only UserData, Af_Led_On and Af_Led_Off, at most 8 lines per batch, arguments limited to letters, digits, space, dot, minus and underscore. The AF lamp flashes twice when the endpoint is up. Nothing is written to firmware; without the card the camera boots as before.

Test plan:

  1. recipe_card.py check: endpoint answers, relay heartbeat younger than 45 s.
  2. One harmless value: recipe_card.py raw 'UserData Set StillImageControlNo2ParamStandardSaturation P1' (with Custom 2 holding Standard). Check in the Image Control menu that Custom 2's saturation is +1.
  3. A full recipe: recipe_card.py send recipes/ricoh-recipes.txt "Reggie's Color Negative" --slot 1. Check Custom 1 in the menu, take a photo with it, then recipe_card.py verify … reads the photo's maker notes and compares them with the recipe.
  4. Power-cycle without the card and check again: do the values stay?

Community recipes

Three files in recipes/ hold recipes published for the GR III / GR IIIx, read on 2026-11-20, with author and source link for each. The values are as published; none were checked on a camera. Reggie's Color Negative links to Reggie Ballesteros' own page (2023-12-29), which matches the bundled values for every setting it lists.

FileSourceRecipes
recipes/luke-taylor.txtLuke Taylor's blog, category Ricoh GR III24
recipes/ricoh-recipes.txtRitchie Roesch's Ricoh Recipes, the free ones from all eight collections; the 7 patron-only recipes are left out38
recipes/gr-blog.txtRicoh's GR Blog (factory Negative Film values; Asakura's Negative Film) and a Kodak Portra gist3

How the published values were turned into settings:

  • An exposure range ("−1/3 to +1/3, typically") becomes its middle, rounded toward 0 to a third of a stop. The note keeps the range.
  • "ISO up to 6400" is iso_max; a single ISO is iso.
  • Luke Taylor's Bleach Bypass toning "White" (Ricoh Superia Summer) is read as the menu's W, Warm; the note says so.
  • Values the firmware has no setting for are left out, with a note: Bleach Bypass toning "Red" (Vintage Fade Film) and Cross Process colour tone "Blue" (Xpro Teal).
  • A setting the page does not give stays out. Ricoh's factory Negative Film values come without white balance.

Checking a file

python3 tools/recipes.py RECIPES.TXT
  • On success it prints every recipe as a dial-in list and exits 0.
  • On a mistake it prints each problem with the recipe name and exits 1, for example Street Mono: Contrast +9 out of range (-4..+4).

The same check runs for every file in recipes/ in python3 -m pytest tools/tests and in the app's unit tests.
